# Android 下拉菜单稳定性

2026-09-12 收到设置页频繁展开菜单后原生崩溃的报告。退出记录只有 `REASON_CRASH_NATIVE`，没有故障线程或原生堆栈，无法据此确定具体故障库。PSS / RSS 是退出记录中的内存指标，不能单凭这些数字判断根因。[Android ApplicationExitInfo](https://developer.android.com/reference/android/app/ApplicationExitInfo)

原实现会在展开时切换设置卡片的 `content-visibility`，显示带模糊和变换动画的弹层，并调用 `scrollIntoView`。同时，全页面的 class 和子节点变化都会触发弹窗焦点检查。这些操作涉及布局、滚动和合成，是本次针对性修正的范围，并非已经取得故障设备上的堆栈定位。

Android 与桌面均使用原来的应用内 `CustomSelect`，保留 Basic、Apple OS 27、WinUI 的配色、圆角、模糊与展开效果。2026-09-19 根据用户反馈撤回系统选项控件，优化限于运行开销：

- 缓存选项节点和按值索引，只更新新旧选中项与键盘指示项。
- 相同选项列表重复刷新时复用节点，保留展开状态与滚动位置。
- 同一时间仅打开一个菜单，列表替换或关闭会取消待执行的滚动；同一帧中的多次键盘导航只滚动最后目标，且不滚动祖先页面。
- 设置卡片保持可见布局，不在展开菜单时切换 `content-visibility`。焦点监听仅观察弹窗根节点与直接挂载到 body 的新弹窗，无关控件和日志更新不会触发全页面检查。

原生诊断补充了退出进程名、信号/退出码。WebView 创建完成后记录当前 Android、设备型号和 WebView 包版本，便于再次出现问题时比较环境；不保存原生内存转储、设备序列号或账号凭据。

## 回归检查

运行 `npm run dev`，打开本机开发地址下的 `/scripts/dropdown-regression.html`，点击“运行重复操作检查”。页面直接使用项目控件和四份样式表，不连接校园网、不修改应用配置。

- 三种主题各执行 2000 次应用内菜单展开和选择，核对值、展示文字和回调，确认没有系统选择控件。
- 检查动态选项、相同列表重复刷新、空列表与禁用状态；确认保留自定义主题菜单。
- 执行 800 次桌面菜单展开，核对互斥、长列表键盘选择及祖先滚动保护。
- 在弹窗显示时改变无关控件与内容，核对焦点监听回调为零，以及 Tab 循环和焦点恢复。

浏览器检查不等同于在故障 Android 设备上的 WebView 中复测。是否消除原报告中的原生崩溃，仍需故障设备复测；若复现，应收集新的退出记录、WebView 环境信息和应用原生崩溃堆栈。
