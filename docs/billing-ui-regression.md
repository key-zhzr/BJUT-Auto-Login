# 计费与界面流程回归

跨端调试入口、模拟数据和源码定位见 [App 与 LuCI UI 开发指引](ui-development.md)。

本轮修正覆盖计费 VPN 策略、登录错误、当前会话入口、手动账号选择、窗口启动与网络阶段反馈。

## 计费行为

- 最低兼容使用系统 DNS；较低兼容使用校园 DNS，未取得物理接口上下文时并发查询有线与 Wi-Fi DNS；高兼容保留 HTTPS 并连接 `172.21.0.16`。
- 最高兼容使用固定校园 IP 的 HTTP，仍受现有 15 分钟临时开关约束；登录表单、资源及跳转只接受受信任校园主机与端口。Cookie 与页面链接在内部保留统一来源，出站 Host、Origin、Referer 与所选传输模式一致。
- 密码错误回到登录页时优先识别服务器的账号密码错误提示；隐藏验证码文字不再被判为图形验证码要求。
- 概览账号状态取自 dashboard 中“状态”标签相邻的值列。缺少该列时保留未知，不根据 `useFlag` 猜测。
- 已关闭自动登录的账号仍可在手动登录、账号切换和计费入口选择。
- “当前登录账号”通过现有校园自服务跳转取得临时计费会话，不提取密码，也不写入已保存账号的会话池。账单和写操作先核对实际账号，账号变化时要求重新刷新。统一认证改密和校园卡付款仍需要对应的已保存密码。

## 本地界面检查

运行 `npm run dev`，打开 `/scripts/app-regression.html`，点击“运行本轮界面回归”。页面读取当前应用 HTML 和样式，使用 Tauri 官方模拟接口及仅存在于内存的测试偏好；不读取真实应用账号、不发起校园网或付款请求。

检查内容包括：

- 窗口显示请求先于初始网卡快照，慢网络初始化不会阻挡窗口显示。
- 自动登录已关闭的账号仍出现在手动列表，并可读取计费。
- 当前会话显示真实账号及 dashboard 状态，账单查询携带正确账号与会话来源。
- SSO 选择标记不会成为校园卡付款账号。
- 计费账号、校外访问、刷新在桌面和移动端均为同高横排，长账号不会撑出屏幕。
- jfself 图片验证支持取消后重新查询；WebVPN 支持换图、填写后继续短信验证。测试图片与验证码均为本地模拟数据，不访问学校验证码。
- 网络阶段更新、等待期间进度增长，以及过期事件不会覆盖新进度。
- 控制台与诊断进度条出现、消失时的动画；退出过程中重新检测不会被旧动画隐藏，诊断失败也会收起进度条。
- 路由与当前设备复用同一计费工作台，切换来源后恢复对应账号、分页和充值入口；路由端每页 100 条，第二页展示不同数据且保留总条数。
- 路由断开后立即恢复本机计费查询，稍后返回的旧路由数据不会覆盖本机余额或锁住刷新按钮。

`npm run test:frontend` 另覆盖统一路由计费适配器：完整导出 50,000 条上限、缺页/条数/字段变化拒绝导出、账号隔离、断线与来源切换后取消旧结果、未知状态拒绝，以及同一 MAC 多会话时按精确会话索引注销。

下拉菜单重复展开、Android 应用内菜单、键盘与焦点回归见 [Android 下拉菜单稳定性](android-dropdown-stability.md)。

## 设备复测

Windows 平台配置必须显式保留 `visible: false`，因为平台的窗口数组会替换通用配置；后端在发布应用状态前完成尺寸与位置恢复。需在 Windows 上冷启动验证无默认位置闪现，并检查最大化、多显示器与缩放变化。

Windows 启动时首先注册 Tauri 官方单实例插件，早于其他插件、窗口、托盘和后台任务初始化。再次打开应用只还原和聚焦第一个窗口；已最大化窗口保持最大化。覆盖以下设备复测场景：正常显示、最小化、关闭到托盘、启动尚未完成时连续双击、退出后重新打开。每种情形只应保留一个主进程与托盘图标；第二次启动不应再次读写配置或执行登录任务。WebView2 自身的子进程不算第二个应用实例。

启动保护还会串行化通知窗口建立前的初始化阶段，避免同时冷启动时第二个进程找不到第一个进程的通知窗口而继续启动。Windows CI 运行真实系统互斥量测试，检查并发等待、释放后的继续启动和初始化线程意外退出后的恢复；这些测试不创建界面，也不读取应用配置。

计费 HTTP / 校园 DNS 的真实部署响应、macOS 冷启动显示时间，以及原报告中的 Android 原生崩溃，仍需在相应设备和校园网络复测。本地模拟页面与单元测试不能证明这些真实环境行为。

新版一卡通会话协议与验证边界见 [一卡通会话适配](mobile-portal-session.md)。

WebVPN 的 CAS 页面通过 `config.captcha = {type:'image', id:...}` 和脚本动态创建验证码控件。解析只读取该配置中的字面量，不能把脚本中的 `<img src="' + captchaUrl() + '">` 模板当作真实图片。回归包含动态配置、仅有模板但未要求验证、静态图片与外站地址拒绝；图片请求限定在学校 WebVPN 的 CAS 代理路径内。已用新建匿名会话验证实际图片请求返回 HTTP 200 / PNG，未识别或填写验证码。接口验证不替代真实设备上的图片显示与提交验收。

## Windows 计费入口的栈占用

用户报告 `20d7cab` 可正常打开计费中心，后续构建在 2% 处卡住并退出。2% 也由前端在发起请求前设置，不能据此证明请求已经执行到后端的会话锁或登录阶段。

新增验证码超时将计费 Future 逐层按值嵌入；后台取消及命令包装继续放大它。使用同一本地 Rust 1.96.1 / macOS arm64 工具链测量未执行的 `get_billing_center` Future：

| 版本 | 对象大小 |
| --- | ---: |
| `20d7cab` | 13,520 字节 |
| `c486198` | 36,496 字节 |
| 本轮修正 | 960 字节 |

这些是 Future 对象大小，并非实际峰值调用栈，也不能单独证明用户设备的异常代码。修正将请求在构造包装器之前放到堆中，消除该路径的 `clippy::large_futures` 警告。命令与包装器分别有 16 KiB / 4 KiB 的回归上限，防止新增功能再次放大状态。

Windows CI 除页面解析外，也在调试与优化构建中执行 1 MiB 栈上的普通计费启动、Rustls 客户端初始化和 Tauri 响应适配。测试以空密码在首个 HTTP 请求前结束，不访问真实账号或付款接口。其他回归验证验证码等待不占网络预算、取消请求关闭验证码窗口、后台停止读取，以及已经开始的写操作完成后才返回。校园网络下的实际页面加载仍需用新构建在设备上复测。

## 长日期范围

上网记录、充值明细和业务办理记录自动拆为最多 60 个自然日的区间，首尾不重叠，按服务端倒序拼接。全局分页先汇总各段条数，只获取所需页；CSV 遍历所有页并对合计执行 50,000 条上限。合计使用十进制定点相加，缺失的分段汇总不伪装为完整总计。读取失败、条数变化或页面不完整时整个请求失败，不导出部分记录。回归覆盖跨年/闰日、跨段跨页、空段、完整导出、汇总金额及中途失败。
