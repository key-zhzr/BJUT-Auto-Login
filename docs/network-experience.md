# 网卡、双栈与检测调度

控制台以“✓ IPv4 xx ms · × IPv6 超时”的形式显示双栈互联网状态，详细原因保留在悬停提示和网络诊断中。门户返回认证成功与外网探测通过是独立结果。公共探测只限制地址族，由系统选择路由与源地址，兼容 TUN 路由和临时 IPv6 地址；不再把公共探测强制绑定到认证网卡。HTTP 代理被禁用，以免代理隐藏实际连接的地址族。IPv4 使用 Cloudflare / ipify，IPv6 使用 ipify 的 IPv6 专用入口 / Microsoft IPv6 连通性入口，并验证状态码或预期正文。各地址族的目标并发执行，任一有效响应即可完成该地址族的检查，单项超时 3 秒。失败显示“超时”或“未确认”，不能据此断言 IPv6 不可用。

Windows、macOS、Linux 可在设置页直接点击网卡列表选择认证接口，“自动选择”也作为列表选项。选择同时影响身份采集、轻量轮询和登录请求。自动模式沿用平台的校园物理接口选择；指定模式在该网卡消失或失去 IPv4 后等待恢复，不回退到另一接口。虚拟/VPN 接口仅用于展示。Android 展示系统网络列表，继续由现有 Network 绑定机制选择校园 Wi-Fi，暂不提供手动选择接口。Wi-Fi 已联网但独立 lgn 有线未认证时，仍以有线门户的只读会话查询核对认证状态，避免把 Wi-Fi 的公网结果当作有线认证成功。

手动登录从安全检查开始计时，展示网关确认、等待其他操作、认证准备、提交和联网复核的耗时。取消与提交使用同一后端操作状态；取消可以先于登录 IPC 到达。准备阶段结束后、真正发送认证之前再次核对网络身份。认证或注销开始提交后关闭取消入口，并以只读探测核对联网结果；响应未知时仍不自动重复提交。

认证后任一地址族完成有效联网校验即可结束前台验证，另一地址族继续后台检测并更新控制台。认证请求失败不会因为另一路互联网可用而改写为登录成功。登录反馈结束后保留 15 秒，结果、总耗时及阶段耗时同时写入持久日志。

自适应检测默认开启，可以在设置中关闭。以当前网络档案或全局间隔为基础：后台连续成功 3 次后延长至 2 倍，6 次后延长至 5 倍（通常上限 300 秒，尊重更长的用户基础间隔）；有地址但探测失败时，前 3 次暂用 5 秒间隔，随后后台放缓。省电/Android 息屏状态至少使用前台 60 秒、后台 120 秒；移动数据保留前台 120 秒、后台 300 秒下限。稳定后台的接口轮询降至 15 秒，省电时降至 30 秒，系统网络事件仍即时响应。睡眠后发现时间跳变，会重新等待地址并完整检测。

Android 保活服务和界面核心共用 Rust 调度策略；服务保存本轮建议的下次间隔。桌面后台在低频状态下也降低计时器唤醒频率。设置页展示当前有效间隔和原因。

诊断包对新增的 IPv4、IPv6 地址和恢复目标地址进行脱敏。回归测试使用模拟网卡与回环服务，覆盖单栈失败、指定接口消失、取消/提交竞态、稳定/断网/省电调度及脱敏，不使用校园账号或重启真实网卡。
