# 网卡、双栈与检测调度

控制台以“✓ IPv4 xx ms · × IPv6 超时”的形式显示双栈互联网状态，详细原因保留在悬停提示和网络诊断中。门户返回认证成功与外网探测通过是独立结果。公共探测只限制地址族，由系统选择路由与源地址，兼容 TUN 路由和临时 IPv6 地址；不再把公共探测强制绑定到认证网卡。HTTP 代理被禁用，以免代理隐藏实际连接的地址族。IPv4 与 IPv6 均并行探测 Microsoft、Apple 和 Cloudflare，使用同一套传输与响应校验；IPv6 使用 Microsoft 的 IPv6 专用入口。各地址族的目标并发执行，任一有效响应即可完成该地址族的检查，单项超时 3 秒。失败显示“超时”或“未确认”，不能据此断言 IPv6 不可用。

Windows、macOS、Linux 可在设置页直接点击网卡列表选择认证接口，“自动选择”也作为列表选项。选择同时影响身份采集、轻量轮询和登录请求。自动模式沿用平台的校园物理接口选择；指定模式在该网卡消失或失去 IPv4 后等待恢复，不回退到另一接口。虚拟/VPN 接口仅用于展示。Android 展示系统网络列表，继续由现有 Network 绑定机制选择校园 Wi-Fi，暂不提供手动选择接口。Wi-Fi 已联网但独立 lgn 有线未认证时，仍以有线门户的只读会话查询核对认证状态，避免把 Wi-Fi 的公网结果当作有线认证成功。

手动登录从安全检查开始计时，展示网关确认、等待其他操作、认证准备、提交和联网复核的耗时。取消与提交使用同一后端操作状态；取消可以先于登录 IPC 到达。准备阶段结束后、真正发送认证之前再次核对网络身份。认证或注销开始提交后关闭取消入口，并以只读探测核对联网结果；响应未知时仍不自动重复提交。

认证后任一公共目标完成有效联网校验即可结束前台验证，尚未完成的双栈探测继续后台检测并更新控制台。认证请求失败不会因为另一路互联网可用而改写为登录成功。登录反馈结束后保留 15 秒，结果、总耗时及阶段耗时同时写入持久日志。

自适应检测默认开启，可以在设置中关闭。以当前网络档案或全局间隔为基础：后台连续成功 3 次后延长至 2 倍，6 次后延长至 5 倍（通常上限 300 秒，尊重更长的用户基础间隔）；有地址但探测失败时，前 3 次暂用 5 秒间隔，随后后台放缓。省电/Android 息屏状态至少使用前台 60 秒、后台 120 秒；移动数据保留前台 120 秒、后台 300 秒下限。稳定后台的接口轮询降至 15 秒，省电时降至 30 秒，系统网络事件仍即时响应。睡眠后发现时间跳变，会重新等待地址并完整检测。

Android 保活服务和界面核心共用 Rust 调度策略；服务保存本轮建议的下次间隔。桌面后台在低频状态下也降低计时器唤醒频率。设置页展示当前有效间隔和原因。

诊断包对新增的 IPv4、IPv6 地址和恢复目标地址进行脱敏。回归测试使用模拟网卡与回环服务，覆盖单栈失败、指定接口消失、取消/提交竞态、稳定/断网/省电调度及脱敏，不使用校园账号或重启真实网卡。


常规检查、诊断和手动登录的只读联网验证由 `connectivity.rs` 协调。相同网络代次、接口、物理地址、系统路由、Android Network 标识及兼容策略共用在途请求；极短期成功结果可复用，失败不缓存。公共互联网、双栈和需要时的 lgn 会话检查并行执行。常规检查可在互联网与必要会话条件确定后返回，诊断等待完整结果。手动登录取得任一有效公网响应后即可继续，其他探测后台完成；Android 为保持 Network 绑定生命周期，等本轮探测结束后再释放绑定。

网卡变化会取消旧探测并清空双栈显示，认证提交前也会废弃先前结果。双栈事件携带网络代次和探测编号，前端丢弃较旧结果。诊断期间发生网络或认证变化时，报告标记为需要重新检测，不更新控制台状态，也不提供过期的适配器恢复操作。

仅在成功取得非空的已连接接口列表、并确认全部接口均无对应地址时显示“未配置”；其他物理接口和 VPN 接口也参与此判定。接口读取失败保留未知状态。DNS、TLS、连接中断、响应异常和超时分别显示；原始错误链只用于本地分类，不向事件时间线写入账号、地址或请求参数。

最近网络事件在 `network-events.json` 中保留最多 80 条，诊断页显示最近 12 条。固定文案记录选卡、联网状态、自动登录关闭以及停止重试的原因；相同状态合并，每次登录单独保留。登录反馈即使在“仅错误”日志等级下也写入完整日志文件，界面仍遵循日志过滤设置。

桌面窗口位置、正常尺寸和最大化状态保存在独立的 `window-geometry.json` 中；最小化或全屏时不覆盖正常尺寸。拖动与调整大小延迟合并写入，关闭窗口时立即保存。恢复时按当前显示器工作区和缩放比例约束位置、大小，防止外接显示器拔除后窗口落在屏幕之外。

代码分工：`internet_probe.rs` 负责公共目标，`dual_stack.rs` 负责地址族与失败分类，`connectivity.rs` 负责任务共享和失效，`network_diagnostics.rs` 负责报告与脱敏导出，`network_events.rs` 负责决策记录，`window_geometry.rs` 负责窗口恢复；前端分别由 `network-experience.ts`、`login-progress-view.ts`、`network-events-view.ts`、`diagnostics-view.ts` 和 `keyboard-navigation.ts` 管理对应交互。

## 系统出口与网卡直连

控制台和诊断页的系统出口行直接订阅同一份 `connectivity` 结果，保留原探测编号与时间；诊断不能以另一组目标的结果覆盖控制台。网卡直连调用同一探测实现，并额外绑定认证网卡。Windows/macOS 使用对应接口索引，Linux 使用设备绑定，绑定失败不回退至默认路由。桌面直连 DNS 也绑定该网卡；Windows 从 IP Helper 读取每张网卡的 DNS，macOS 在诊断时读取所选 Wi-Fi 或有线的 DHCP / scoped resolver。使用接口提供的 DNS 与 AliDNS 公共回退，不把 TUN Fake-IP 用于物理连接。Android 的 DNS 和 socket 使用同一个 `Network`；系统出口取默认 Network，直连取认证物理 Network，不依赖临时的进程网络绑定。网卡能否在界面手动选择不影响直连资格。

TUN 仅接管 IPv4 时，系统出口的 IPv6 仍可能走物理网络；这里测试系统实际路由，不代表强制所有流量经过 VPN。每个地址族只使用该族的 TCP 目标，HTTP 代理不参与。3 秒预算包括 DNS、连接、TLS 与正文校验；返回成功会取消其他目标，超时表示这些探测目标尚未通过，不等于整个地址族不可用。
